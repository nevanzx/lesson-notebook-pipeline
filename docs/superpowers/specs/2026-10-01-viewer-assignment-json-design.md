# Assignment as Encrypted JSON + Native Viewer Presentation

Date: 2026-10-01 · Status: draft for review

## 1. Context

Today the graded assignment lives **inside** the lesson HTML. Section 7 mounts the
`assignment` shell component (`v2/skeleton/components/assignment/component.js`, ~32 KB),
whose CSS/JS is inlined into every built lesson. The sanitized assignment object ships as
`LN.data.<key>`, AES-256-GCM encrypted at rest (v2.9) as `{lnenc:1,v:1,iv,ct}`. The lesson
iframe boots the component; it asks the embedding page for the key over `postMessage`, the
student viewer (`checker/app/viewer.html`) relays that to the Worker `POST /unlock`, and the
component decrypts and renders the full-screen deck.

Two problems follow from the UI living in every lesson:

1. **Changing the assignment UI means rebuilding every lesson.** The deck markup, flow, and
   styling are frozen inside each shipped `.html`.
2. **The lesson carries a renderer it does not need.** Section 7 is the only consumer, yet
   every lesson inlines ~32 KB of deck JS plus CSS.

This design retires the in-lesson assignment entirely. Section 7 becomes a slim card; the
assignment travels as one **encrypted JSON block** in the lesson file; and the viewer app
renders it natively, so the deck UI has exactly **one** home — the viewer.

## 2. Goals / non-goals

Goals:

- (a) The lesson ships **no assignment renderer** and **no plaintext question text** — only a
  self-contained encrypted JSON block plus non-secret metadata.
- (b) The **student viewer** (`viewer.html`) and the **teacher viewer**
  (`teacher-viewer.html`) both decode that block, decrypt it, and render the assignment
  natively, with parity to today's experience (identity gate, time lock, DAG + flat walk,
  guards, encrypted submit).
- (c) Changing the assignment UI happens **only** in `checker/app`, with no lesson rebuild.
- (d) The v2.9 guarantees hold: ciphertext at rest; the universal key lives only in the Worker
  secret and the teacher's local `build/key/unlock.key`; the Worker still releases it only to
  the app origin on the configured window.
- (e) `build.py` keeps authoring-time validation (dag graph, flat item mix, MILO blueprint)
  and keeps writing the teacher grading key.
- (f) The legacy in-lesson path is **removed**; old lessons are regenerated by the user.

Non-goals:

- No scoring/AI grading change; the checker (`teacher.html`) and the submission envelope
  (`{k:"RSA-OAEP-256+A256GCM", wk, iv, ct}`) are untouched.
- No Worker change: `/unlock` already releases the key to the app origin.
- No change to `dag-craft.md` / `question-craft.md` authoring law, except that flat now also
  gets a reviewer pass (see §4.4).
- No migration code for old lesson files.

## 3. Lesson file format

### 3.1 Section 7 is a slim card

No `data-component="assignment"` mount, no data object, no deck. A static section: the
assignment title, the weekday/time window in words, and a line pointing at the HTML Viewer.
The Section 7 agent writes it as ordinary section prose (see §4.3). It is not interactive.

### 3.2 The encrypted block

`build.py` injects one inert JSON script into the shell at a new marker,
`<!--__ASSIGNMENT_BLOCK__-->` (placed immediately after `__META__` in `shell.html`):

```html
<script type="application/json" id="ln-assignment">
{"lnenc":1,"v":1,
 "iv":"<base64 12-byte iv>","ct":"<base64 AES-256-GCM ciphertext>",
 "pub":"<teacher RSA-OAEP-256 SPKI public key, base64>",
 "keyId":"<teacher key id>",
 "title":"<assignment title, plaintext>",
 "week":"7","subject":"<subject>",
 "window":{"day":"wednesday","tz":"Asia/Manila"}}
</script>
```

- `iv`/`ct` encrypt the **sanitized** assignment object (answers already stripped), exactly
  the bytes `encrypt_assignment_data` produces today.
- `pub`/`keyId` replace the values build.py currently injects as `__PUBKEY__` / `__KEYID__`
  into the component JS. They are non-secret.
- `title`, `week`, `subject`, `window` are non-secret and make the block self-contained so
  the viewer needs nothing else. The existing `ln:week` / `ln:subject` / `ln:window-day` /
  `ln:window-tz` meta tags remain (the checker still reads them).
- The block is inert JSON: opening the lesson in a browser, another viewer, or an AI yields
  no question text.

## 4. Build pipeline

### 4.1 Trigger and build.json

An assignment exists when the workdir contains `assignment.json` (see §4.2).
`build.json`:

```json
{
  "title": "Week 7 — …",
  "theme": "ledger",
  "layout": "app",
  "components": ["break-even-lab", "true-false"],
  "assignment": "dag",
  "dag": { "levels": 3, "max_nodes": 10 },
  "window": { "day": "wednesday", "tz": "Asia/Manila" },
  "week": "7",
  "subject": "…",
  "output": "Week7-Notebook.html"
}
```

- `"assignment"` is the mode selector, `"dag"` (default when omitted but `assignment.json`
  present) or `"flat"`; it must match `assignment.json.mode`.
- `"assignment"` must **not** appear in `components` — that is now an error with a migration
  hint ("drop it; put the questions in assignment.json").
- `"dag"` and `"window"` keep their current meaning and validation.

### 4.2 `assignment.json`

A new workdir-root file, strict JSON, authored by the assignment agents (§4.4). Shape is
identical to today's `LN.data.<key>` object — one of:

- dag: `{mode:"dag", title, scenario, intro?, nodes:[{id,level,isLeaf,question,outcome,
  choices:[{label,text,nextNodeId}],finalOutcome?}, …]}` with author-side `points`.
- flat: `{mode:"flat", intro?, items:[10 mc · 4 tf · 4 id · 2+ sa]}` with `ans`/`aliases`/
  `key_points`/`rubric`/`max_points`.

`build.py` reads it, runs the existing `validate_assignment` / `_validate_assignment_dag` /
`_validate_assignment_flat`, sanitizes it with the existing `sanitize_assignment_data` logic
(refactored to operate on the object, not on `data.js` text), encrypts with
`ensure_unlock_key`, and writes the block. The teacher key (`build/key/<stem>-key.json`,
with `teacher_key_pem`, dag `optimal`, answers) is written exactly as today.

### 4.3 Section 7 slim card

`parts/NN-<id>.sections.html` holds the card (title, "opens in the HTML Viewer" note,
window in words). It has no data file, or an empty one. build.py's outline contract is
unchanged: Section 7 is still an outlined section whose `<h2>` matches.

### 4.4 Assignment authoring + review (unchanged law, new home)

- **DAG (default):** preserved per-level fan-out — for each level, an **author agent** writes
  strict-JSON nodes, then a **separate reviewer agent** checks that level against
  `dag-craft.md` (its reviewer checklist) before assembly into `assignment.json`. This review
  is explicitly retained.
- **Flat:** the author agent writes `assignment.json` per `question-craft.md`; a **separate
  reviewer agent** now checks the deck (mix, ±1-word MC, single-flip tf, the copy test, the
  MILO blueprint, independent answer re-derivation) before it is accepted. (Today flat had no
  separate reviewer.)
- The Section 7 card agent runs separately and only needs the title + window.

### 4.5 Removals in build.py

- Do not load `assignment` from `components`; delete the `__PUBKEY__`/`__KEYID__` injection.
- Delete `extract_assignment`, `_data_obj_span`, and the text-level
  `sanitize_assignment_data` / `encrypt_assignment_data`; replace with
  `load_assignment(workdir)`, `sanitize(obj)`, `encrypt_to_block(...)`.
- Reject a lesson that mounts `data-component="assignment"`.
- Keep `ensure_teacher_keys` and `ensure_unlock_key`; keep the `dag`, `window`, `week`,
  `subject` validation.

## 5. Viewer app

### 5.1 Shared deck module (single source of truth)

Port the deck into `checker/app/lib/assignment/`:

- `deck.js` — the UI and flow (Begin card, identity gate, DAG + flat walk, progress, guards,
  submit), ported from `v2/skeleton/components/assignment/component.js`. Exports
  `mountAssignment(root, data, opts)`.
- `crypto.js` — `decryptAssignment(keyB64, envelope)` (AES-256-GCM via WebCrypto) and the
  submission envelope builder (RSA-OAEP-256 + AES-GCM), preserving
  `{k:"RSA-OAEP-256+A256GCM", wk, iv, ct}`.
- `block.js` — `extractAssignmentBlock(htmlText)` → `{envelope, pub, keyId, title, week,
  subject, window}`; reads the `#ln-assignment` script and falls back to meta tags.

Invariants carried over verbatim: `show()` is the sole recompute point for Next-disabled and
progress dots; every answer writer calls `bump()`; the deck refuses to render before
`state.identified`. These are covered by the retargeted smoke test (§7).

### 5.2 Student viewer (`viewer.html`)

1. On file pick/drop/URL load, read the lesson **as text** (`file.text()`, or `fetch(url)`
   for links), keep the text, then create the blob URL for the iframe as today.
2. `extractAssignmentBlock` on the text. If the block is present, show a **persistent
   Assignment bar** (block `title`, week/subject, the window). Tapping it opens a native
   fullscreen overlay hosting the deck.
3. Deck key: call `POST ${workerUrl}/unlock` directly from the viewer page (same origin gate
   as today). On `{ok:true,key}` → `decryptAssignment` → `mountAssignment(..., {gateBypass:
   true})`. On `out-of-window` → the Wednesday notice; on any other failure → the
   "open in the official viewer" card.
4. Submit downloads `Lastname, Firstname - Week N - Subject.json` from the viewer page.
5. **Remote link fallback:** if the URL cannot be fetched as text (cross-origin without
   CORS), the lesson still renders in the iframe but the Assignment bar is hidden with a note
   to download the file and open it locally. Picked files always work.

### 5.3 Teacher viewer (`teacher-viewer.html`)

Same overlay and deck module. The key comes from the locally dropped/pasted
`build/key/unlock.key`, held in memory only (never localStorage, never a served file). The
time gate is bypassed for preview, as today. New-format lessons use the block; there is no
legacy iframe path.

### 5.4 Removed viewer code

- `checker/app/lib/unlock.js`'s iframe-relay handler and the `postMessage` protocol
  (`ln-unlock-request` / `ln-unlock-response`) — replaced by a direct `requestUnlockKey
  (workerUrl)`. The Worker is unchanged.
- The legacy in-lesson rendering path (plaintext/gated) is deleted everywhere.

## 6. Security

Unchanged guarantees: the lesson holds only ciphertext plus a non-secret public key; the
universal key never enters a served/saved file; the plaintext assignment exists only
transiently in viewer memory; the Worker releases the key only to the app origin on the
configured window, fail-closed. The deck now runs in the top-level app origin rather than a
same-origin iframe, but that origin is exactly the one the Worker already trusts, so the
trust boundary is identical — not widened.

## 7. Testing

- **Python (`tests/test_assignment_*.py`, `test_build.py`):**
  - built lesson has `#ln-assignment` with `iv`/`ct`/`pub`/`keyId`/`title`/`week`/`subject`/
    `window`; `ct` decrypts with `unlock.key` to the sanitized object;
  - no `"ans"`, `"aliases"`, `"key_points"`, or `"points"` string anywhere in the lesson;
  - no `data-component="assignment"`, no deck JS/CSS inlined;
  - `assignment.json` dag/flat validation still rejects the same faults;
  - teacher key file content unchanged; `"assignment"` in `components` is a hard error.
- **Node (`checker/app/test/`):** block extraction (script + meta fallback); AES-GCM
  decrypt round-trip; submission envelope still `RSA-OAEP-256+A256GCM`; deck render parity
  for dag and flat (typed-answer answers do not strand Next).
- **Smoke:** `v2/tools/assignment_smoke.js` repointed to load a built lesson, extract the
  block, and drive the viewer deck (dag + flat); `LAYOUT OK` at desktop and `--width 390`.
- **Manual E2E:** build a lesson → open the `.html` in `viewer.html` → Assignment bar appears
  → deck opens on the window day (and is blocked outside it) → submit downloads the file →
  grader decrypts it.

## 9. Rollout

1. `build.py` + `shell.html` + Python tests: build emits the block, no inlined deck; a lesson
   fails if it still mounts the component.
2. `checker/app/lib/assignment/*` + tests: extraction, decryption, deck parity.
3. `viewer.html` + `teacher-viewer.html` wiring; delete the iframe relay.
4. `v2/tools/assignment_smoke.js` retarget; run it + `layout_smoke.js`.
5. Docs sweep and skill version bump. Regenerate the affected lessons.

Each step lands green before the next.

## 10. Open questions

None. Decisions: encrypted self-contained JSON block in the lesson; Section 7 slim card;
native deck in the viewer shared by student and teacher pages; dedicated `assignment.json`
authored with a reviewer subagent (per-level for DAG); legacy in-lesson path removed; Worker,
checker, and submission envelope unchanged.
